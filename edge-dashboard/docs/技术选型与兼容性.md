# 界面的实现原理与技术约束

记录这套界面「怎么跑起来的、为什么这么做、写代码时必须守什么规矩」。
换人或换设备时先看这篇，能省掉重复踩坑。

---

## 一、总体结构

界面分两层，**一份源码，一次编译**：

```
src/pages/*/index.ux      Vela 风格的界面源码（template + style + script）
        │
        │  node tools/build-preview.js   ← 编译
        ▼
preview/index.html        单文件 HTML（内联数据、图标、样式、运行时）
        │
        │  浏览器全屏打开（linux/start.sh）
        ▼
M1 的 Linux + 外接触控显示器
```

为什么要自己写一个编译步骤，而不是直接写 HTML？三个原因：

1. **界面源码按 Vela 的盒模型写**（`<div>` 默认就是列方向 flex 容器、
   `<text>` 是行内盒）。这种写法比手写 HTML+CSS 更简洁，也更贴近嵌入式 GUI 的习惯。
2. **将来若要迁到别的平台**（例如换一块支持 openvela 的板子，
   或改成 LVGL 原生应用），`.ux` 这层的改造成本最低——
   布局语义已经写在源码里了。
3. **编译期能做校验**：`tools/check.js` 可以在不启动浏览器的前提下
   查出标签不闭合、class 未定义、路由指向不存在的页面等问题。

编译脚本 `tools/build-preview.js` 具体做了这些事：

| 步骤 | 说明 |
| --- | --- |
| 模板转换 | `for` / `if` / `{{}}` → 运行时可重渲染的 DOM 描述 |
| 标签映射 | `<text>`→`span`、`<scroll>`→`div`、`<image>`→`div` |
| 样式作用域化 | 每个页面的 CSS 前缀化到 `[data-page="页面名"]`，避免互相污染 |
| 脚本转换 | 去掉 `import`/`export`，注入运行时桩件（router / prompt / 数据源） |
| 数据内联 | 把 `store.js` 直接内联进 HTML，**保证断网可用、零外部请求** |
| 图标内联 | PNG 以 base64 内联，不产生额外文件请求 |

产出的 `index.html` 约 100 KB，双击即可打开，不依赖服务器和网络。

## 二、为什么不用 openvela 快应用（原先的方案）

最初的方案是 Vela 快应用（`.rpk`），理由是「改界面不用重编固件」。
但**M1 实训箱不支持 openvela**，`.rpk` 需要 openvela 的快应用运行时
（QuickJS + LVGL + Yoga + 快应用框架）才能加载，这是硬依赖，没有降级办法。

连带失效的能力：

| 能力 | 状态 |
| --- | --- |
| `@system.velaclaw`（端侧 AI 对话） | **不可用**，语音助手改为本地指令模式 |
| `vapp hap://app/<包名>` 启动 | 不可用 |
| `adb push` 到 `/data/app/` 部署 | 不可用 |
| U1P（GD32F470）跑界面 | 不可能——裸机/RTOS 芯片，无操作系统与浏览器 |

所以界面层改为「浏览器全屏看板」，跑在 M1 的 Linux 上。
`docs/部署到openvela.md` 保留，供你以后拿到 openvela 板子时参考。

### 各家方案对比

| 方案 | 零构建 | 离线可用 | 触控 | 改界面成本 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **浏览器 kiosk 全屏（采用）** | ✓ | ✓ | ✓ | 换一个文件 | **采用** |
| Vela 快应用 `.rpk` | ✗ | ✓ | ✓ | 换文件但需重推 | M1 不支持，弃用 |
| LVGL 原生 | ✗ | ✓ | ✓ | 重编译 + 重烧录 | 成本高，弃用 |
| Electron | ✗ | ✗（要装运行时） | ✓ | 换文件 | 离线装不动，弃用 |
| Qt / PyQt | ✗ | ✓ | ✓ | 重部署 | 需重写界面，弃用 |

## 三、写界面必须守的约束

### 1. 布局：`<div>` 就是 flex 列容器

这是最容易出错的一点。在 Vela 语义里：

- `<div>` 默认 `display: flex; flex-direction: column`
  → **所有横向排版必须显式写 `flex-direction: row`**
- `<text>` 是行内盒，没有宽高概念，不要给它设 `width`/`height`
- `<scroll>` 是可滚动容器

浏览器预览页专门对齐了这套盒模型（`span` 行内、`div` 为 flex 列容器），
否则预览与预期会不一致。

### 2. CSS 只用子集

**可用**：`flex-direction`、`flex-wrap`、`flex`、`justify-content`、
`align-items`、`width`/`height`、`padding`/`margin`、`border-radius`、
`background-color`、`color`、`font-size`、`font-weight`、`text-align`、
`position: absolute`（浮层用）、`rgba()`。

**不要用**：伪类、伪元素、CSS 变量、`transition`/`animation`、媒体查询、
后代/兄弟选择器、`grid`。

本工程所有样式都只用上面这些属性。

### 3. 模板语法

- 循环：`for="{{list}}"`，循环体内用 `$item` / `$index`
- 条件：`if="{{cond}}"`
- 插值：`{{expr}}`，**只能出现在标签之间**

  ⚠️ **不要在属性值里拼接多个绑定**。踩过的坑：

  ```html
  <!-- 错误：两个绑定塞进一个 style，样式会丢失 -->
  <div class="badge" style="{{$item.bg}}; {{$item.color}}">

  <!-- 正确：外层承担背景色，内层承担文字色 -->
  <div class="badge" style="{{$item.bg}}">
    <text class="badge-text" style="{{$item.color}}">{{$item.statusText}}</text>
  </div>
  ```

- 事件：`onclick="handler"` + `tid="参数"`，
  处理函数里用 `e.target.attr.tid` 取参数（`tid` 是保留属性名，
  不要用 `data-xxx` 之外的自定义属性传参）

### 4. 数据与生命周期

- 页面数据放 `private`，直接 `this.xxx = yyy` 即驱动更新
- 生命周期：`onInit` / `onShow` / `onRefresh`
- 跳转：`router.push({ uri: '/path' })`，`router.back()`
  —— 路径以 `src/manifest.json` 的 `router.pages[].path` 为准

### 5. 脚本

只用 ES6 基础语法（`const`/`let`、`map`/`filter`/`forEach`、
`Object.assign`、字符串拼接），不用可选链、空值合并等较新语法，
保证在最老的浏览器内核上也能跑。

## 四、界面与数据的关系

```
src/common/store.js   ← 唯一数据源（区域 / 车辆 / 记录 / 派单逻辑）
        │
        ├── Home      概览卡（summarize）
        ├── Dispatch  车辆卡与任务清单（getCars / getZones / dispatchTask）
        ├── Zones     区域与路线（getZones）
        ├── Records   历史轮次（getRecords）
        ├── System    设备与链路（getCars）
        └── Voice     本地指令表（直接调用 store 的方法）
```

**接真实数据时只改 `store.js`**：把 `dispatchTask` 换成真正向 M1 / 车端
发指令，把状态回写 `ZONES`，然后调用各页面的刷新即可，页面层不用动。

VelaGuard 原规划的功能对照：

| 规划功能 | 界面落点 | 数据来源 |
| --- | --- | --- |
| 功能一 区域与任务清单管理 | 「区域与路线」app | `ZONES` |
| 功能二 任务派单与结果回收 | 「巡检调度台」+ 桌面快捷坞 | `dispatchTask` / `cancelTask` |
| 功能三 异常中断与人工处置 | 调度台异常卡 + 一键取消 | `ZONES.status === 'blocked'` |
| 功能四 巡检覆盖的基础汇总 | 桌面概览卡 + 「巡检记录」app | `summarize()` / `RECORDS` |

## 五、语音助手的降级设计

由于没有 `@system.velaclaw`，语音助手按「本地优先」实现：

1. **本地指令表**（`tryLocal`）：巡检控制类指令不经过任何模型，
   直接操作数据源。覆盖：
   - 开始本轮巡检 / 取消全部未完成任务
   - 现在哪些区域没查完
   - 某区域为什么阻塞
   - 生成巡检报告（汇总计数）
2. **外部 AI（可选）**：若将来接上任何 HTTP 形式的大模型接口，
   把 `ask()` 里 `aiReady` 分支换成真实请求即可，
   `probeAI()` 换成一次探测请求。

好处是：**离线可用、演示不会因为网络或额度失效而卡住**。

## 六、后续可扩展方向

1. **真实数据接入**：`store.js` 的 `dispatchTask` 改为通过 C1 链路
   （HTTP / TCP / 串口）向 M1 发「任务单」，状态回执按任务序号写回。
2. **U1P 声光按键**：界面入口已做好（一键取消），
   在 M1 侧读按键/驱动 LED 蜂鸣器，通过同一链路通知界面。
3. **S3 麦克风**：替换 `VoiceAssistant/index.ux` 的 `recognize()`，
   把「按住说话」接到真实语音识别。
4. **换分辨率**：改 `manifest.json` 的 `config.designWidth` 重新生成即可，
   布局是纯 flex，没有写死坐标。
