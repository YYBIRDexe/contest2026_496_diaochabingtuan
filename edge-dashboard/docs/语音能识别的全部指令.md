## 一、唤醒方式

| 项 | 值 |
| --- | --- |
| 唤醒词（当前） | **Hello, openvela**（`hello openvela`，说的时候中间可稍停顿） |
| 解码候选 | `hello open vela` / `hello open` / `open vela` / `open` |
| 唤醒引擎 | 本地 vosk 英文小模型 `vosk-model-small-en-us-0.15`，**不联网** |
| 中文唤醒词 | `小陈同志` / `小陈` / `陈同志`（模型 `vosk-model-small-cn-0.22`） |
| 换语言 | `WAKE_LANG=zh bash ~/voice_pipeline/唤醒.sh`（模型、唤醒词、候选三样一起换） |
| 换词补丁 | `linux/_patch_wake_hello.py`（hi openvela → Hello, openvela；含实测数据与备份） |

> ⚠️ **两个换词的硬约束**（实测踩出来的，别踩回去）：
> ① `openvela` 是生造词、**不在英文小模型词表里**（`helo` 也不在，"hello" 在），
>    所以 grammar 里必须写成 **`hello open vela`**（拆开），而匹配词表写
>    归一化后的 `hello openvela`（两边都去空格再比对）。
> ② **候选不能只留一条**：grammar 越窄，越容易把环境噪声**硬凑**成唤醒词。
>    用现场中文干扰音频复测：窄候选误触发 **1/6**，带宽松兜底候选 **0/6** —— 所以留四条。
>    而**匹配词表只认完整唤醒词**（缺前缀的碎片一律不认），这是 09-19 收紧的结论。

**也可以不喊唤醒词**：界面上的「说话」按钮会直接触发同一套链路。

## 二、界面按钮怎么用（两段式）

```
第一次按下「说话」
   ├─ 设备响上行提示音「嘀嘟」= 开始
   └─ 立刻开始录音（按钮变橙、显示「结束」）

第二次按下「结束」
   ├─ 设备响下行提示音「嘟嘀」= 结束
   ├─ 立即停止录音（不等 VAD 判句尾）
   └─ 音频送云端识别 → 解析意图 → 下发小车 → 语音回报
```

**不按第二次也能用**：说完约 0.8 秒静音后 VAD 自动收尾。

> **结果可能是"晚到"的（09-19 改）**：云端 ASR 实测 1 秒到几分钟不等。
> 界面不再死等一个请求 —— 按完第二次只等 8 秒，拿不到就先显示
> 「录音已结束，正在识别…」，结果由界面每 2 秒轮询
> `GET /api/voice/records` 补进会话区。
>
> 同一个轮询也让**喊唤醒词触发的那一轮**出现在会话区里（以前只有按按钮
> 触发的那轮才看得见，喊唤醒词说的话界面完全不知道）。
> 换句话说：无论用按钮还是唤醒词，说过的都会出现在同一个会话记录里。

提示音规格（`speech-bridge.py` 与 `voice_button.py` 一致）：

| 提示音 | 频率 | 含义 |
| --- | --- | --- |
| 上行双音 | 1200 → 1600 Hz | 开始听 |
| 下行双音 | 1600 → 1200 Hz | 结束 |
| 单声高音 | 1800 Hz | 出结果了 |

#### `battery`（电量）—— 本轮新增

**实测识别**（10 个说法，9 个命中）：

| 说法 | 结果 |
| --- | --- |
| 小车的电量怎么样了 | ✅ `battery` |
| 查一下电量 | ✅ `battery` |
| 电池还有多少电 | ✅ `battery` |
| 剩余电量 | ✅ `battery` |
| 2号车电量 | ✅ `battery` |
| 电够不够 | ✅ `battery` |
| 电量 | ✅ `battery` |
| 电池 | ✅ `battery` |
| 还能跑多久 | ❌ 没命中（不在词表里） |
| 现在状态怎么样 | ✅ 正确归到 `status`（没被抢走） |

**它会怎么回答**：

| 情况 | 语音播报 |
| --- | --- |
| 四台都读到 | `最低1号百分之44，最高4号百分之72` |
| 只有一台读到 | `只有2号车在线，电量百分之59` |
| 部分读到 | `3号、4号读不到；最低1号车百分之44` |
| 一台都读不到 | `四台小车都联系不上，读不到电量` |

**技术细节**：
- 话题 `data` 是**毫伏**，按 2S 锂电 **6.0 V(空) ~ 8.4 V(满)** 线性估算百分比
- 播报里同时念电压，百分比只当参考（锂电放电曲线不是直线）
- **只读**：只订阅话题，不发任何指令，车不会动
- 并发读四台，最坏 **4 秒**返回（原来串行要 32 秒）
- 实测读数：1号 7.047 V ≈44%、2号 7.423 V ≈59%、3号 7.696 V ≈71%、4号 7.729 V ≈72%

#### `car_check` 的正则（说法太散，靠正则兜）

| 正则 | 匹配例子 |
| --- | --- |
| `连(?:得\|的)?上.{0,6}(?:小车\|车辆\|车)` | 连上小车了吗 |
| `(?:小车\|车辆\|车).{0,4}连(?:得\|的)?上` | 小车连得上吗 |
| `(?:小车\|车辆\|车).{0,4}(?:在\|连\|通)(?:线\|上)` | 小车在线吗 / 车通吗 |
| `(?:小车\|车辆\|车).{0,4}(?:都)?在(?:不在\|吗)` | 车都在不在 / 小车在吗 |
| `(?:检查\|看看\|查一下).{0,4}(?:小车\|车辆\|车)` | 检查一下小车 |

> ⚠️ 正则**别写太松**：曾用 `.{0,3}(?:线|上|吗|么|不)`，
> 结果"小车现在状态怎么样"里的"状态怎**么**"让 `么` 对上，把 `status` 误判成 `car_check`。

## 四、指定控制哪几台车

| 说法 | 效果 |
| --- | --- |
| 「2号车」 | 只控 2 号 |
| 「1号和3号」 | 控 1、3 号（**09-19 修**：原来只认第一个车号，会退化成只控 1 号） |
| 「所有车」「全部」「四台车」「大家一起」 | 控全部 |
| **「编队」「一起」「一块」「协同」「集体」** | **控全部**（09-19 新增，见下面的事故说明） |
| **不说** | 只用配置里默认的那台（`$CAR_IP` = 1 号车） |

车号同时接受**阿拉伯数字与中文数字**（`1` / `一`，`4` / `四`）。

### ⚠️ 09-19 的事故：「小车编队，后退0.5米」只有 1 号车动了

**现象**：用户说这句话，只有 1 号车后退 0.5 米。
**记录里的证据**：云端判成 `backward {distance_m: 0.5}` —— **没有 targets** →
`ROBOTS` 为空 → `ros_car.py` 退回 `$CAR_IP` → 只有 1 号车。

**三个根因一起修**（补丁 `linux/_patch_fleet_targets.py`，三个文件都带备份）：

| # | 根因 | 修法 |
| - | --- | --- |
| 1 | 云端提示词的多车清单里没有"编队"，模型照规则就不给 targets | `agent_slow.py` 把"编队/一起/一块/协同/集体"写进多车清单，并加 few-shot：**「编队+动作」按动作理解 + targets 全部车**；`start_formation` 只用于明确的队形实验 |
| 2 | 助手只信云端给的 targets，没有兜底 | `voice_button.py` 慢路径：云端没给 targets 时，用**用户原话**判一次（`_extract_robots`） |
| 3 | 本地规则把"编队"排在"后退"前（都是 2 字），整句被判成编队实验（正方形/0.8m/30s） | `nlp_parse.py` 加消歧：句子里有移动词**且**有距离/角度时按移动处理（编队只当"一起"）；真正的队形实验（排成正方形/给间距/跑多久）不受影响 |

**实测（注入 TTS 音频走真实链路，dry-run 不动车）**：

```
识别（6.95 秒）：小车编队后退零点五米。
  -> 慢路径(agent) 判定：backward {"distance_m": 0.5, "targets": [1, 2, 3, 4]}
     目标车：[1, 2, 3, 4]
记录：step backward {'distance_m': 0.5, 'targets': [1,2,3,4]} → robots='1,2,3,4'
```

设备自带回归同时全绿：`nlp_parse --selftest` 24/24、`vcmd --selftest` 9/9、`run_tests.py` 71/71。

## 五、出错时它会说什么

出错会**先响一段本地提示音，再用语音说一句**（都不长）：

| 内部标识 | 它会说 | 提示音（Hz） |
| --- | --- | --- |
| `net` | 网络不通 | 700↓560↓440 |
| `asr` | 识别失败 | 700↓560↓440 |
| `asr_to` | 识别超时 | 700↓560↓440 |
| `nohear` | 没听清 | 760↓620 |
| `nomatch` | **没听懂** | 760↓620 |
| `unsafe` | 这条指令不安全 | 900→620↓420 |
| `noaction` | 这条指令还没配置 | 700↓560 |
| `execfail` | 执行失败 | 700↓560↓440 |
| `vcmderr` | 命令解析出错 | 700↓560↓440 |
| `micbusy` | 麦克风被占用 | 560↓440↓340 |
| `recfail` | 录音失败 | 560↓440↓340 |
| `nomic` | 没听到声音 | 760↓620 |
| `nocar` | 小车联系不上 | 700↓560↓440 |

> **关键设计**：提示音走板载扬声器、**不依赖网络**；语音那句靠 TTS 磁盘缓存，
> 所以**断网也说得出来**（13 条话术已全部预合成进 `tts_cache/`，实际有 103 个 wav）。

## 七、识别流程

```
说唤醒词（或按界面「说话」）
                ↓
     提示音「请讲」→ 录音（VAD 自动判句尾 / 第二次按下立即结束）
                ↓
        ┌───────┴───────┐
   本地规则命中      没命中
   （nlp_parse.py）  （agent_slow.py 云端）
        ↓                ↓
   直接执行 <10ms    云端模型判意图 2~10s
        └───────┬───────┘
                ↓
     安全检查 → 下发（UDP/rosbridge）
                ↓
            语音回报结果
```

**快档（本地规则，推荐默认）**：命中关键词 → 零延迟、100% 可控
**慢档（云端）**：规则没命中且句子里有「小车/实验」→ 交云端模型

> **设计原则**：机器人控制链路里，**能确定的就别交给模型**。
