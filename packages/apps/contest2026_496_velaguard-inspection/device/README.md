# E5 触控演示版（方案 A）

> 在 **M1/U2P 实训箱的 E5 触控屏**上演示 VelaGuard 巡检调度台：
> **手指点「开始巡检」→ 四台车按固定路线执行 → 1 号车遇障停车 → 弹出阻塞告警 → 轮次汇总**
>
> 全流程约 **9 秒**自动播放，操作者只需点一下。
> **本文档说明它到底是什么、不是什么、怎么跑、怎么改。**

---

## 〇、一句话定性（**先看这段，别跳过**）

> **这是一个「交互与状态流转」的演示程序，运行在 U2P 的 Ubuntu 上，用 Firefox 全屏显示。**
> **它不控制真实小车，也不是 openvela 应用。**

| 别人可能会问 | 事实 |
|---|---|
| 跑在 openvela 上吗？ | ❌ **不是。** 跑在 U2P（Horizon X3M，**Ubuntu 20.04**）的 Firefox 里 |
| E5 是什么？ | U2P 的**外接触控屏**（1920×1080，HDMI + Type-C 接 U2P） |
| 点了车会动吗？ | ❌ **不会。** 界面里的车辆位置来自**应用内置的路线数据**，与真车无连接 |
| 那什么是真的？ | ✅ **程序逻辑全真**：派单、固定路线、逐段推进、遇障停车、阻塞判定、改派/顺延/取消、轮次汇总 —— 全部是 `src/` 里真实的状态机在跑 |
| 数据是假的吗？ | ⚠️ 是**内置模拟数据**。界面状态栏自带「模拟器演示」标签，**这是刻意保留的诚实标注，不要裁掉** |

**为什么不在 openvela 上跑？**
openvela 模拟器（`goldfish-arm64-v8a-ap`，竞赛分支 `dev-ai-contest-2026`）的 QuickApp 运行时存在缺陷 ——
执行 `vapp hap://app/<包名>` 会触发**递归断言**并复位板子：
`nuttx/sched/misc/assert.c:840: up_puts("Reset board on recursive assert:");`
**官方自带 demo 同样崩溃**（已实测复现），因此不是本应用的问题，是上游固件缺陷。
排查过程与证据见 `../../模拟器部署-20260920/进度与恢复步骤.md` 第十三节。

## 一、快速上手（两条命令）

在**任意能 SSH 到设备的机器**上执行：

```bash
# ① 复位到干净的初始画面（录制前必做）
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/reset.sh"

# ② 起演示（如果没在跑）
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/run-demo.sh"

# 停止
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/run-demo.sh --stop"

# 看状态
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/run-demo.sh --status"
```

**设备信息**

| 项 | 值 |
|---|---|
| 地址 | `192.168.1.104`（用户 `sunrise`，已配免密 SSH） |
| 系统 | Ubuntu 20.04.5 LTS / kernel 4.14.87 / aarch64 |
| 屏幕 | E5 触控屏，**1920 × 1080 横屏** |
| 部署目录 | `~/velaguard/demo/` |
| 访问地址 | `http://127.0.0.1:8126/demo-e5.html`（**只绑 127.0.0.1**，不对外暴露） |
| 浏览器 | Firefox，`--kiosk` 全屏 |

> ⚠️ **端口是 8126**：8123 被另一套实时看板占用，8124/8125 也被别的服务占了。改端口见第五节。

## 三、它是怎么跑起来的（架构）

```
U2P (Ubuntu 20.04)
├── python3 -m http.server 8126        ← 静态服务，只服务 ~/velaguard/demo/
│      └── demo-e5.html
└── firefox --kiosk --no-remote        ← 全屏显示到 :0（= E5 屏）
       └── demo-e5.html
            ├── <script> #1  bundle        ← 与正式版**同一份**应用代码
            └── <script> #2  演示宿主        ← 只有这层是演示专用的
```

**关键设计：应用代码（bundle）与正式版完全相同。**
`tools/build-demo-e5.js` 是从 `build/ui-home.html` **派生**的：沿用前面那段 bundle，只替换末尾的宿主脚本。
所以演示里的每个交互走的都是 `src/` 里真实的状态机，**不存在"演示专用逻辑"**。

**演示宿主比正式宿主多三件事：**

1. **横屏流体排布覆盖**（见下节，这是设备适配的核心）
2. **大号触控按钮**「开始巡检」/「复位」（手指点得到，`#bar` 固定在底部）
3. **自动演示序列 `demoRun()`** —— 按**真实动作名**派发，等于替用户点了界面上的按钮：
   ```js
   vg.dispatch('startRound', '')            // = 点首页「开始本轮巡检」
   vg.navigate('Dispatch')                  // 切页
   vg.dispatch('inject', target.id)         // = 点调度台「1 号车遇障」
   vg.navigate('Records')
   ```
   不直接改 `store` 内部状态，所以界面反应与应用真实行为一致。

### 演示时间轴

| 时刻 | 动作 | 画面 |
|---|---|---|
| 0.3s | `startRound` | 概览卡转「巡检进行中」，四区转「进行中」 |
| 1.6s | `navigate('Dispatch')` | 巡检调度台：四台车 + 任务清单 T-100x |
| 2.6s | `navigate('Map')` | 真实 ROS 地图，4 台车沿路线移动，进度 40%/25%/22%/22% |
| 3.4s | 选一个 `running` 区域 → `navigate('Dispatch')` → `inject` | 入口大厅转「阻塞」 |
| 4.0s | —— | 告警浮层：`CAR-1 遇到障碍已停止，其余车辆保持原位，建议单独改派或取消。` |
| 9.0s | `navigate('Records')` | `第 1 轮：入口大厅阻塞、主通道已完成…`，统计 `3 已完成 / 1 阻塞` |

> ⏱ **为什么注入障碍定在 3.4s？**
> 速度 0.8 m/s，最短路线 2.3 m + 停留 1.5 s ≈ **4.4 s 跑完一个区**。
> 晚于这个时间注入，`injectObstacle()` 会如实回绝「当前是已完成，无法注入故障」。
> 第一版定在 16 s 就是这么错的 —— **靠截图验证抓出来的**，不是猜的。

## 四、横屏适配（**改之前必读**）

应用基础样式 `src/common/styles.js` 是**按 720×1280 竖屏写死的**：

```css
#app  { width: 720px; min-height: 1280px; }
.tile { width: 330px; }        /* 竖屏两列 */
```

E5 是 **1920×1080 横屏**。直接放上去会被挤成中间一条窄柱、四周大片黑边（设备实拍确认过）。

**演示宿主只覆盖「与屏幕方向耦合」的排布规则**，组件内部的字号/圆角/配色全部沿用原样式：

| 覆盖项 | 原（竖屏） | 现（横屏） |
|---|---|---|
| `#app` | `width:720px` | `width:100%` 铺满 |
| `.screen` | 无限制 | `max-width:1500px` 居中 |
| `.grid` | flex 两列 | **12 列栅格** |
| `.tile`（应用磁贴） | `330px` 固定 | `span 4` → **每行 3 个** |
| `.grid > .lrow`（区域条） | `330px` 固定 | `span 3` → **每行 4 个** |
| `.mapwrap` | 固定 680px | **限宽 1080px** 居中 |
| `.chat` | `640px` 固定 | `calc(100vh - 470px)` |

**三个必须知道的坑（都踩过）：**

1. **区域条的行内写了 `width:330px`**（模板里），不加 `!important` 解不开 → 4 条放不下会溢成 3+1 两行。
2. **`.tile:nth-child(2n){margin-right:0}`** 是竖屏两列时写的，在 `grid+gap` 下 2n 是**中间列**，必须一起覆盖，否则列宽不齐。
3. **地图不能铺满整宽**：SVG 的 `viewBox` 只有 500×303，里面 `font-size="15"` 是按那个尺度定的。
   铺到 1800px 会把文字和线宽一起放大 **3.6 倍**，区域名直接压垮画面。
   限到 1080px（放大 **2.16 倍**）才既用上宽屏又不糊。

## 五、怎么改

### 改应用逻辑（推荐）

**改 `../src/` 下的源码**，然后重新生成，**不要手改 `demo-e5.html`**：

```powershell
cd ..                                     # 回到工程根目录
node tools/build-demo-e5.js               # 重新生成 build/demo-e5.html
node tools/verify-demo.js                 # 验证（会出 5 张 1920x1080 截图）
scp build/demo-e5.html sunrise@192.168.1.104:~/velaguard/demo/demo-e5.html
ssh sunrise@192.168.1.104 "md5sum ~/velaguard/demo/demo-e5.html"   # 核对与本地一致
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/reset.sh"
```

> ⚠️ **`verify-demo.js` 的截图尺寸必须保持 `1920,1080`。**
> 之前用 `720×1280` 验过 —— 正好与设计的竖屏一致，**永远发现不了横屏排布问题**，白验了一轮。

### 改演示时间轴 / 按钮

改 `../tools/build-demo-e5.js` 里 `<script>` 那段字符串（`demoRun()`），然后按上面重新生成。

### 改端口

`run-demo.sh` 和 `reset.sh` **两个文件都要改** `PORT=`。

### 录制现场要求

见 **`../docs/E5-开拍执行单.md`** —— 含机位、反光规避、手部动作、开拍前自检清单。

## 七、与真车的关系（**最容易误解的地方**）

**这台设备上确实有一套能控制真车的系统，但和本演示是两回事。**

| | 本演示（方案 A） | 真车任务系统 |
|---|---|---|
| 位置 | `~/velaguard/demo/demo-e5.html` | `~/velaguard/linux/m1_task_api.py` |
| 端口 | `8126` | 未启动（需手动拉起） |
| 车辆数据 | **内置模拟数据** | `car_state.py` 每 5s **实时探测真车** |
| 能否控制真车 | ❌ 不能 | ⚠️ **代码具备，但硬件输出被开关关闭** |
| 接口 | 无 | `dispatch_task` / `cancel_task` / `reassign_task` |

**真车任务系统的现状：**

- 四台真车**在线**（`192.168.1.201`–`.204`，ping/SSH/rosbridge `9090` 全通）
- 任务流程**真的跑通过**（`task_api.json` 里有 `acceptance-*` 验收记录，含成功改派到 `Robot02` 的痕迹）
- 但每个任务最终都以 `"reason": "hardware_output_disabled"` 收尾 —— 因为：
  ```python
  # m1_task_api.py:56
  def hardware_output_enabled() -> bool:
      return os.environ.get("VELAGUARD_HARDWARE_OUTPUT", "0") == "1"
  ```
  **默认关闭。这是刻意的安全设计。**

**要让真车动起来（方案 B）还缺：**

1. `routes.json`（路线 → 动作序列映射）—— **当前不存在**，缺了它派单会返回 `route_plan_invalid` 503
2. 以 `VELAGUARD_HARDWARE_OUTPUT=1` 启动服务
3. **实测**（车会真的在实验室里跑，需清场 + 有人盯 + 能急停）

> ⚠️ **A 与 B 不能简单相加。** 要让"点开始巡检 → 真车跑 → 真车遇障"成立，
> 需要把本演示的按钮接到真车任务 API 上，是一件真正的开发工作，不是改个开关。
> 详见 `../../模拟器部署-20260920/进度与恢复步骤.md` 与真车任务系统的验收记录。

## 九、排错

| 现象 | 原因 / 处理 |
|---|---|
| E5 上还是旧看板 | 旧 kiosk（`8123`）还活着。**只要有 Firefox 实例存活，新 kiosk 只会开个 200×200 小标签页** → 跑 `run-demo.sh`（它会先 `pkill firefox`） |
| 屏幕纯白 | Firefox 用了 `--allow-file-access-from-files`。该参数在 `http://` 下会**破坏页面加载**，只在 `file://` 时才加 |
| 弹出「恢复上次页面」挡住看板 | `user.js` 里的会话恢复没生效 → 跑 `run-demo.sh` 重写 profile |
| 点了没反应 | ① 先确认点的是**蓝色**「开始巡检」（不是灰色「复位」）；② 跑 `reset.sh`；③ 仍不行检查 E5 的 Type-C 线是否插在 U2P 上 |
| 中间大段空白 | **正常。** 内容按 1500px 限宽居中 |
| 端口冲突 | 改 `run-demo.sh` 与 `reset.sh` 里的 `PORT=`（当前 `8126`；`8123/8124/8125` 已被占用） |
