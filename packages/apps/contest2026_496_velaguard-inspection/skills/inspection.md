# 多机器人分区巡检

把固定区域（入口大厅 / 主通道 / 展项区 / 设备区）的检查任务分派给 1~4 号车，
跟踪任务状态，并在异常时主动告警、给出处置建议，跨轮次记住未完成区域。

> 部署位置：`/data/agent/skills/inspection.md`
> ⚠️ **先确认目录名**：源码 Kconfig 默认是 `/data/ai_agent`（技能在 `/data/ai_agent/skills/`），
> 而官方文档与大赛指引写的是 `/data/agent/skills/`，板级 defconfig 没有覆盖这个宏。
> 以设备上**实际存在的目录**为准——push 错目录不报错、也不生效。
>
> **本文件里的路线名、区域名与阈值都必须与 `src/common/data.js` 保持一致**，
> 改了数据表就要同步改这里，否则动作码对不上。

## When to use

用户提到这些意思时使用本 Skill：
- 开始巡检 / 巡检一下 / 检查一下 / 查一遍
- 某某区域（入口大厅、主通道、展项区、设备区）
- 几号车 + 动作（前进、后退、左转、右转、停止）
- 任务进度 / 查完了吗 / 哪些区域没查完 / 汇总 / 报告
- 停止 / 急停 / 取消 / 别查了

## How to use

1. **先查车队状态**：调 `fleet_status` 拿到每辆车的在线状态与电量。
   - 离线车**一律不得派单**，并在回复里说明。
   - 电量低于 20% 的车不派任务。
2. **确认路线**：本系统的路线是**端侧预设的固定路线**，只有四条，且只认编号：
   `route_entrance` / `route_aisle` / `route_exhibit` / `route_equipment`。
   不要尝试生成新路线或传入坐标——任务单里不携带坐标与速度。
3. **下发**：调 `car_move`（单车动作）或 `formation`（编队）。
   参数必须落在安全范围内（见下表），越界则**拒绝下发并说明原因**。
4. **播报**：回复会由边缘层（M1）用扬声器播报，所以**回复要适合朗读**——
   短句、不带 Markdown、数字用中文更稳（如「零点五米」）。
5. **主动任务**：按下面「主动任务声明」登记。

## 区域与车辆映射

| 区域 | 默认车辆 | 路线编号 | 路线长度 |
|---|---|---|---|
| 入口大厅 | 1 号车 | `route_entrance` | 2.3 m |
| 主通道 | 2 号车 | `route_aisle` | 2.6 m |
| 展项区 | 3 号车 | `route_exhibit` | 2.7 m |
| 设备区 | 4 号车 | `route_equipment` | 2.7 m |

整条固定巡检路线 ≈ **10.3 m**，四个区域各跑一小段、单步 ≤ 1 m。

## 动作码与参数（必须与 vcmd_actions.json 一致）

| 说法 | 动作码 | 参数 | 安全范围 |
|---|---|---|---|
| 前进 / 后退 | `FORWARD` / `BACKWARD` | `distance_m` | 0.05 ~ 5.0 |
| 左移 / 右移 | `STRAFE_LEFT` / `STRAFE_RIGHT` | `distance_m` | 0.05 ~ 5.0 |
| 左转 / 右转 | `TURN_LEFT` / `TURN_RIGHT` | `angle_deg` | 1 ~ 360 |
| 停止 / 急停 | `STOP` | — | 无参数 |
| 编队 | `START_FORMATION` | `formation / spacing_m / duration_s / robots` | spacing 0.3~3.0 / duration ≤ 300 |

## 任务状态语义

待执行 → 进行中 → 完成 / 阻塞 / 取消

判定规则（与 `src/common/store.js` 的状态机一致）：
- 下发成功并收到开始回执 → 进行中
- 收到完成回执 → 完成
- 收到异常回执，或**连续 20 秒无回执** → 阻塞（失联）
- 整条任务超过 180 秒 → 阻塞（超时）
- 用户明确取消 → 取消
- 车辆离线 → 该区域标为离线，任务不派出

## 主动任务声明

| 类型 | 触发条件 | 动作 |
|---|---|---|
| **定时主动** | 每 5 分钟 | 汇总四区域覆盖情况并主动播报，**无需用户提问** |
| **事件主动** | 收到异常回执 / 车辆离线 | 立即告警 + 给出改派建议 |
| **阈值主动** | 连续 20 秒无回执 | 判定失联，将该车**移出本轮**，其区域顺延 |
| **上下文主动** | 每轮巡检**开始前** | 读 `memory_read`，若上轮有未完成区域，**主动提醒**是否优先安排 |

记忆内容：用 `memory_write` 记录「上一轮各区域完成状态 + 失败车号 + 失败原因」。

## 安全规则（最高优先，任何情况下不得违反）

1. **「停止 / 急停」优先于任何行进动作**，且**只能由规则精确命中产生**，
   不允许由模糊匹配或模型推断产生。
2. **车端本地安全逻辑最高优先**：车端遇障会自行停车。
   openvela 与 M1 **均不接管电机 PWM**。
3. **离线车不得被派单**；不安全的广播动作必须由各车自行决定是否执行。
4. 参数越界 → **拒绝下发**并说明，不得静默改成边界值。
5. 认不出意图时 → **明确说不认识**，不得猜测下发。

## 告警文案模板

- `"3 号车未就绪，是否只用 1、2、4 号车继续？"`
- `"2 号车遇到障碍已停止，其余车辆保持原位，建议单独改派或取消。"`
- `"连续 20 秒未收到 4 号车回报，判定失联，已将其区域顺延。"`
- `"本轮汇总：入口大厅完成、主通道已完成、展项区阻塞、设备区完成；展项区已顺延至下一轮。"`

## Example

User: "开始巡检"
→ fleet_status
→ 需要时按区域派单：入口大厅 → 1 号车 / 主通道 → 2 号车 /
  展项区 → 3 号车 / 设备区 → 4 号车（路线为对应的 route_* 编号）
→ "已派单：入口大厅给 1 号车、主通道给 2 号车、展项区给 3 号车。
   4 号车离线，已移出本轮，设备区顺延到下一轮。"

User: "现在哪些区域没查完"
→ fleet_status（或读巡检状态）
→ "主通道进行中、展项区阻塞、设备区离线，入口大厅已完成。"

User: "小车编队，后退0.5米"
→ formation(action="BACKWARD", distance_m=0.5, robots=[1,2,3,4])
→ "四辆车一起后退零点五米。"
   （群体词「编队」→ 四辆全动，**演示前必须确认场地安全**）

User: "今天天气不错"
→ 不调用任何工具，回复"这句话我理解不了，可以说「开始巡检」或「2 号车前进」。"
   （**认不出就不下发，这是设计目标，不是失败**）
