## ⚠️ 〇、先读这段：2026-09-20 在实机上体检出的三件事

这三条都是实测得到的，会直接影响你按本单子操作的方式：

### 1. NSH 控制台**从宿主机够不到**（最重要）

模拟器是用 `xvfb-run` 一类方式起的，跑在 **Xvfb 虚拟显示 `:99`** 上（`Xvfb :99 -screen 0 1280x800x24 -ac`）。
Xvfb **没有窗口管理器**，所以模拟器窗口收不到键盘焦点。实测：

| 尝试 | 结果 |
|---|---|
| `adb -s emulator-5554 shell ...` | `error: closed` |
| 模拟器控制台 `event text ...` + `event send EV_KEY` | 注入成功，但日志/屏幕**零回显** |
| `adb forward tcp:2323 tcp:23` + telnet（guest 里 telnetd 在跑） | TCP 能连，**但一个字节都不返回** |
| `xdotool`（含 XTEST 与 `--window` 直投） | `_NET_ACTIVE_WINDOW` 不支持，无效 |

**结论：不要在"从 SSH 里敲 NSH 命令"上花时间。** 必须有**人能看见并操作**模拟器窗口。
所以 `ai_agent`、`vapp` 这类命令，只能在一个**真实的图形会话**里手工敲。

> 想知道 NSH 到底收过什么命令？看日志（`-show-kernel` 把串口输出全写进去了）：
> ```bash
> grep -nE '^goldfish-armv8a-ap>' ~/openvela/emulator.log | tail -20
> tail -40 ~/openvela/emulator.log | sed 's/\x1b\[[0-9;]*[A-Za-z]//g'
> ```

### 3.1 ⚠️ 重编固件会清空 `/data`

`cmake_out` 重建时会重新生成 `vela_data.bin`，**`/data` 下你推过的一切都会没**
（应用、字体全丢）。重编后必须重新推：

```bash
adb push /tmp/font /data/                                              # 字体
adb push ~/app.ux        /data/app/com.velaguard.inspection/app.ux
adb push ~/manifest.json /data/app/com.velaguard.inspection/manifest.json
```

好消息是 agent 会自己在 `/data` 下建目录，所以现在有：
`/data/agent/` 与 **`/data/ai_agent/`** → **Skill 该推 `/data/ai_agent/skills/`**。

### 3.2 磁盘不足会让编译失败（已解决）

`/home/ggbird/openvela` 在 sda3，重编前只剩 **2.3 GB**，而编译要 5~6 GB。
已验证的解决办法（把构建输出挪到根分区，实测 2.3G → 7.4G 可用）：

```bash
sudo mkdir -p /var/vela-build/cmake_out
sudo mv ~/openvela/cmake_out/* /var/vela-build/cmake_out/ 2>/dev/null || true
sudo mount --bind /var/vela-build/cmake_out ~/openvela/cmake_out
sudo chown -R $USER:$USER /var/vela-build/cmake_out     # 不改属主会写不进去
```

> ⚠️ **bind mount 重启后失效**，需要重新挂。

### 5. ✅ 关键结论（2026-09-20 04:xx，最终定位）

#### 5.0 🎯 根因：**`.ux` 必须经官方工具链编译，不能手写直推**

官方 `quickapp_manual.md` 的流程是：

> `1. 打开 AIoT-IDE，点击「文件」>「新建项目」`
> `2. 在 AIoT-IDE 中点击 banner 栏的「模拟器」按钮`
> `3. 点击 banner 栏「打包」按钮，生成 dist/xxx.debug.rpk`

对比官方 demo 的设备端文件，**页面文件是 `.js`，不是 `.ux`**：

```
demo/pages/appfunction/index.js        ← 10530 字节的编译产物
demo/app.js                            ← 293 行
```
文件头是工具链包装：
```js
export default function(global, globalThis, window, $app_exports$, $app_evaluate$){
...
var $app_template$ = function (vm) { ... }
$app_exports$.default.template = $app_template$;
// manifest 里 "packageInfo": { "toolkit": "2.0.3", ... }
```

**本机构建链现状：仓里没有工具链，VM 上没有 node/npm**（工具链是 AIoT-IDE 那个图形化 IDE 自带的）。
→ **本工程手写的 `src/*.ux` 无法直接部署**，必须先编译。

#### 5.1 三方独立对照（各自冷启动、单次启动、无干扰）

字体修好后（见 5.4），三份应用分别单独测试：

| 应用 | 形态 | md5 | 色块数 | 主色 | 渲染 |
|---|---|---|---|---|---|
| **官方 demo** | 工具链编译产物（5 页，完整 manifest） | `f69630d886` | **78** | `#f0f0f0` 46% | ✅ **完整渲染**（"AppFunction 测试" + "备忘录：" + 圆角框，**中文正常**） |
| 本工程应用 | 手写 `app.ux`（bundle + 动态喂 HTML） | `f3e447d9ca` | 74 | `#001020` 50% | ❌ 只有背景色 |
| probe 应用 | **官方编译产物**改包名 + 仅留 1 页 | `f3e447d9ca` | 74 | `#001020` 50% | ❌ 只有背景色 |

> **probe 那一行是关键**：它用的**就是官方 demo 的同一批编译文件**，只改了包名、删掉 4 个页面、去掉 `deviceTypeList`。
> 它**也不渲染** → 说明问题**不在"是否编译过"，而在 manifest / 页面注册的完整性**。

#### 5.2 已确认的事实（全部有实测）

| 项 | 结论 |
|---|---|
| 框架能不能渲染 | ✅ **能**（官方 demo 中文、英文、圆角框全部正常） |
| 应用能不能被加载 | ✅ 能（屏幕变成各应用 manifest 里的 `backgroundColor`） |
| 会不会崩 | ✅ 不崩（多次冷启动 assert 恒为 0） |
| 本工程应用为何空白 | ❌ 入口结构/manifest 不完整，框架不认（**不是代码逻辑问题**） |
| LVGL 图形栈 | ✅ 正常（`lvgldemo` 一直能跑） |

#### 5.3 官方 demo 的正确 manifest 写法（照这个改）

```json
"router": {
  "entry": "pages/appfunction",          ← 入口是**完整页面路径**，不是 "index"
  "pages": {
    "pages/index":       { "component": "index" },
    "pages/appfunction": { "component": "index" }
  }
}
```
本工程写的是 `"entry": "index"` + `{"index": {"component":"index","path":"/"}}` —— **写法不对**。
另外官方 manifest 还带 `minPlatformVersion: 1000`、`deviceTypeList: ["watch"]`、
`features[]`、`packageInfo.toolkit` 等字段，本工程都缺。

#### 5.4 ✅ 字体：必须直接放 `/data/font/` 根下（踩过，已修）

源码里字体是**按名字**找的：
```c
CONFIG_FONT_DEFAULT_NORMAL_NAME "MiSans-Regular"
CONFIG_FONT_DEFAULT_BOLD_NAME   "MiSans-Demobold"
frameworks/runtimes/feature/modules/prompt/font.cpp:
  #define FONT_DEFAULT_NORMAL_NAME "MiSansW_Regular"
  #define FONT_DEFAULT_BOLD_NAME   "MiSansW_Demibold"
```

官方文档写 `adb push ./font /data/` —— 其中 **`./font` 本身就是解压出来的那一层**。
照抄这条命令会推成 **`/data/font/font/*.ttf`（多一层）**，框架按名字找不到 → **所有文字渲染成豆腐块**。

**正确做法**（推 ttf 本身）：
```bash
unzip -o docs/zh-cn/contest_2026/quickapp/attachment/font.zip -d /tmp/font
for f in /tmp/font/font/*.ttf; do
  adb -s emulator-5554 push "$f" "/data/font/$(basename $f)"
done
```
修好后官方 demo 的中文从**豆腐块变成正常显示**——这是本次最有用的一条发现。

#### 5.5 ⚠️ 每次重启模拟器 `/data` 都会被清空

`vela_data.bin` 是 256MB FAT16，启动时被重建。所以**每次冷启动后都要重新推应用和字体**。
（这一条我早期不知道，导致多个"空白"结论其实是在"应用根本没部署"的状态下得出的。）

#### 5.6 ⚠️ 串口控制台要长期可用：FIFO 写端必须有人一直持有

QEMU 的 stdin 接 FIFO 时，**写端一关就读到 EOF 并自杀**。脚本里 `exec 3<>$FIFO` 只在脚本存活期间有效。
**正确做法：起一个后台 keeper 长期持有写端**：
```bash
setsid nohup bash -c "exec 3<>'$FIFO'; echo \$\$ > ~/.fifo-keeper; while true; do sleep 3600; done" &
```

#### 5.7 下一步：把应用改造成框架认的形态

两条路，**推荐第 1 条**：

1. **用 AIoT-IDE 编译本工程**（官方正路）
   - 在一台有图形界面的机器上装 AIoT-IDE，打开本工程 → 打包 → `dist/*.debug.rpk`
   - 解包后 `adb push` 到 `/data/app/com.velaguard.inspection/` → `vapp`
   - **但要注意**：本工程为了绕开"未验证的系统 router 模块"而采用了自写路由 +
     `this.html` 动态喂 HTML 的写法，**这套写法本身也没被验证过框架是否支持**。
     用工具链编译后仍需实测。
2. **照官方 demo 的形态重写入口**
   - `manifest.json` 按 5.3 的写法（`entry: "pages/xxx"`、完整字段）
   - 页面拆成 `pages/<name>/index.ux`，**用框架原生 `<template>` 声明结构**，
     而不是运行时注入 HTML 字符串
   - 然后仍需走第 1 条去编译

> **给接手人的提醒**：本工程 `src/` 下的 `.ux` 是"源码"，**不能直接部署**。
> 这两件事必须分开看：源码写对了 ≠ 设备上能跑。
