# E5 触控演示 · 开拍执行单

> 目标镜头：**手指点 E5 屏 → 车跑固定路线 → 弹出避障报错**
> 全程约 **9 秒**自动播放，你只需要点一下。
> 设备：`192.168.1.104`（U2P，跑 Ubuntu 20.04）+ E5 触控屏（1920×1080）

## 一、车怎么放

**结论：车不进画面，或者只做背景。**

为什么：这个镜头演示的是**调度台的交互与状态流转**，车的位置**不影响**屏幕内容 ——
界面里的车辆位置来自应用内置的路线数据，不是实时定位。

**三种放法，按推荐排序：**

| 方案 | 怎么放 | 适合 |
|---|---|---|
| **A（推荐）** | 车放在**画面外**。镜头只给 E5 屏 + 点按的手 | 最干净，评委一眼看清界面 |
| B | 车放**背景**，离 E5 约 1.5–2 m，在画面右上或左后一角，**不挡屏** | 想暗示"这是给车用的调度台" |
| C | 车放前景左下角，**只露一部分**（半车），做纵深 | 有拍摄经验时用 |

**如果选 B/C，注意：**
- 车**通电但不要动**（别让它跑，屏幕内容跟它无关，动了反而像作假）
- 车头朝向镜头侧，别正对镜头（正对像证件照）
- 车与 E5 之间**不要有遮挡**，尤其别让车挡到 E5 屏幕下半部分的按钮

## 二、E5 与相机怎么摆

### E5 屏

| 项 | 要求 | 原因 |
|---|---|---|
| 朝向 | 稍微**后仰 10–15°**，屏幕正对镜头 | 垂直放会有反光带 |
| 高度 | 中心与镜头齐平（约 1.2 m 台面上） | 避免俯拍变形 |
| 遮挡 | 屏幕上方 30 cm 内不要有强光源 | E5 是镜面屏，顶灯会打出一道白斑 |
| 亮度 | 调到 **70–80%**，不要 100% | 满亮在镜头里会偏白、丢失深色层次 |
| 反光 | 拍之前用手机预览看一眼，**屏幕上不能有窗户/灯管的倒影** | 这是最常见的废片原因 |

### 相机/手机

| 项 | 要求 |
|---|---|
| 位置 | E5 **正前方偏右 15–20°**（不是正对，稍微侧一点有立体感） |
| 高度 | 与屏幕中心齐平，**不要俯拍** |
| 距离 | 让 **E5 屏幕刚好占满画面宽度的 85–90%**，四周留一点边 |
| 稳定 | **必须用三脚架或支架**。9 秒全程手持一定会抖 |
| 对焦 | 锁定在屏幕上，**关掉自动对焦**（手指入画时容易跑焦） |
| 曝光 | 锁定后手动压 **-0.3 ~ -0.7 EV**（屏幕亮，不压会过曝） |
| 参数 | 1080p 60fps（手指动作更顺）；横屏 |

### 手

- 用**食指单指**点，指尖从**画面下方或侧面**入画，**不要从上方压下来**（会挡屏）
- 点完**停 0.5 秒再收手**，让镜头看清按钮反馈
- 指甲干净、袖子别太花（深色纯色最好）

## 三、开拍流程（按顺序做，别跳）

### 第 1 步 · 复位设备（开拍前必做）

在你电脑上执行：

```bash
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/reset.sh"
```

**期望结果**：E5 屏变成
```
2026-09-20 xx:xx:xx   VelaGuard 巡检桌面      [模拟器演示]  4/4 车在线 · 电池 91%
本轮巡检 · 第 0 轮                              固定路线 10.3 m
尚未开始巡检，点下方「开始本轮巡检」
  0          0          0          4          0
已完成     进行中      阻塞      待执行     离线
[六个应用磁贴]
区域状态：入口大厅/主通道/展项区/设备区 —— 全部「待执行」
────────────────────────────────────────────
        VelaGuard 巡检调度台
        点击下方按钮开始本轮巡检
        [ 开始巡检 ]   [ 复位 ]
```

### 第 2 步 · 开录

**先按录制，再等 2 秒**，让画面稳定下来再动手（开头留白方便剪）。

### 第 3 步 · 点按钮（唯一需要你做的操作）

用手指点屏幕底部**蓝色「开始巡检」**按钮（左边那个大的）。

### 第 4 步 · 手离开画面，让它自己播

**手一定要完全移出画面**，然后等。约 9 秒内自动发生：

| 时间 | 屏幕上会看到 |
|---|---|
| ~0.3s | 概览卡变「巡检进行中」，四个区域转「进行中」 |
| ~1.6s | 切到**巡检调度台**：四台车 + 任务清单 T-100x |
| ~2.6s | 切到**地图与路线**：真实 ROS 地图，4 台车沿路线移动，进度 40%/25%/22%/22% |
| ~3.4s | 切回调度台，**入口大厅转「阻塞」** |
| ~4.0s | 弹出蓝色告警：**「CAR-1 遇到障碍已停止，其余车辆保持原位，建议单独改派或取消。」** |
| ~9s | 切到**巡检记录**：`第 1 轮：入口大厅阻塞、主通道已完成、展项区已完成、设备区已完成`，统计 `3 已完成 / 1 阻塞` |

**这段千万别碰屏幕**，一碰就可能打断。

### 第 5 步 · 停录

停在巡检记录页再按停。总时长约 12–14 秒（含前后留白）。

## 四、要重录怎么办

| 情况 | 做法 |
|---|---|
| 想重录整条 | 再跑一次 `reset.sh`，回到第 2 步 |
| 点错了、已经跑乱 | 跑 `reset.sh` |
| 只想回到初始画面（不重开浏览器） | 点屏幕底部「**复位**」按钮 |
| 屏幕卡住不动 | 跑 `reset.sh`（它会关掉并重开浏览器） |

```bash
# 万能恢复命令
ssh sunrise@192.168.1.104 "bash ~/velaguard/demo/reset.sh"
```

## 五、开拍前 30 秒自检

- [ ] E5 屏上是「尚未开始巡检」+ 底部两个按钮（**不是**跑完的状态）
- [ ] 屏幕**没有反光斑**（用手机预览确认）
- [ ] 相机**已锁定对焦与曝光**、已在三脚架上
- [ ] 画面里 E5 屏**四边都没被切掉**
- [ ] 手指试点一下「复位」（右下灰按钮），**屏幕有反应** ← 确认触控链路活着
- [ ] 点完「复位」后画面回到初始态，再开始录

## 七、常见问题

**Q：点了没反应？**
A：先确认点的是**蓝色「开始巡检」**（不是灰色「复位」）。如果两个都没反应，跑 `reset.sh`；仍不行说明触控 USB 线松了，检查 E5 的 Type-C 线是否插在 U2P 上。

**Q：屏幕中间大段空白？**
A：正常。这个应用内容按 1500px 限宽居中，所以左右会有留白 —— 不是故障。

**Q：能拍真实的四台车按调度跑吗？**
A：**不能。** 现在这套演示里的车辆位置是内置路线数据，跟真车没有连接。真车数据在另一套看板（8123 端口）上，但那套没有"点开始巡检→跑路线→避障报错"这条交互链。两者是两套东西，**不要在视频里混着说**。
