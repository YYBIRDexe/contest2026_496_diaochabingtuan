## 目录

- `snapshot/`：从 robot1 取出的原有 agent、命令桥、门禁、看门狗、一次性编队脚本和配置快照。它们是原样备份，不含本次原型改动。
- `evidence/classroom.pgm`、`classroom.yaml`：用于离线路径检查的地图；`scan_overlay.png`：定位时使用的扫描与地图对照图。
- `prototype/formation_planner.py`：从任意**有效且物理可达**的四车位姿，规划到方阵、直线、圆形、菱形。默认自动分配目标槽位，检查地图、车身半径、车间距离和逐车路径；过近时先规划分离步骤。
- `prototype/reconfiguration_session.py`：任务状态机。离线、定位过期/不可信、雷达过期、路径被挡、偏离路线或小车异常靠近时，输出全车停止决定；恢复连接并稳定 2 秒后用新位姿重规划。断电恢复只保存任务意图，不沿用旧路径。
- `prototype/test_reconfiguration.py`：基于上述地图和四车历史位姿的离线回归测试。
- `prototype/offline_plan.py`、`example_state.json`：命令行示例；从保存的位姿 JSON 生成指定队形路径，不连接小车。
- `manifest.json`：交付文件的大小与 SHA-256 校验值，便于以后核对快照。

## 离线验证

在 `prototype` 目录运行：

```powershell
python -m unittest -v test_reconfiguration.py
```

2026-09-18 结果：4 项通过，约 28.5 秒。涵盖四种队形、自动槽位分配与过近分离、断线恢复后重新规划、定位/雷达异常停止、不可用场地拒绝规划、进程恢复后旧路径不复用。四种队形均产生可复验的逐车路径；目标最近车距不小于 0.35 m。这里的“可行”仅指保存的静态地图和历史位姿，不能证明实时障碍物与运动控制安全。

生成离线计划示例：

```powershell
python offline_plan.py square --spacing 0.5 --output square_plan.json
```

也可把 `square` 换成 `line`、`circle` 或 `diamond`，并用 `--state` 指定最新的四车位姿 JSON。生成的 JSON 只是路径建议，不会发送给小车。

## 使用边界与下一步

“无论目前状态”按安全方式实现：只要四车重新在线、位姿和雷达新鲜可信、场地存在安全通路，就从**当时位置**重新规划；离线、充电、定位失败、路线被阻挡或物理上无解时保持停止并等待，不强行移动。极近距离（<0.22 m）也暂停，等待人工确认，因为离线地图无法判断车体是否已经接触。

目前原型只计算路径与 `STOP/waypoint` 决定，不连接 ROS、不申请命令桥租约、不打开硬件输出。实车运行前还需要：

1. 修复定位服务停止时遗留 Docker 子进程的问题，确保每车只启动一套 map_server/AMCL。
2. 将状态机接入编队域的四车实时定位、雷达与健康状态；将逐段目标接入受限速、实时避障和碰撞检查的 ROS 执行器。断连时所有车须由本地看门狗独立停车。
3. 在充电结束、场地清空后，先低速单车验证停车与重连，再逐步做四车实测；确认底盘实际外形尺寸、可用场地边界和速度限制后校准 0.12 m 半径、0.35 m 最小车距等参数。

只有完成上述接入和实车验证，才能宣称四车会自主变成指定队形。
